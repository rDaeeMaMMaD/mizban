# میزبان

## درگاه خودمیزبان مدیریت سرویس‌ها و مدل‌های هوش مصنوعی

> میزبان را روی هاست یا سرور خودتان نصب کنید، چند سرویس و مدل هوش مصنوعی را از پنل مدیریت کنید، و فقط با **یک رابط واحد** با آن‌ها کار کنید.

**میزبان** یک درگاه مرکزی برای هوش مصنوعی است؛ با زبان پی‌اچ‌پی و پایگاه‌داده مای‌اس‌کیوال، بدون وابستگی خارجی و بدون فریم‌ورک سنگین.

به‌جای اتصال مستقیم هر برنامه به ده‌ها سرویس خارجی، برنامهٔ شما فقط با میزبان صحبت می‌کند و میزبان درخواست را به سرویس مناسب می‌فرستد.

```text
برنامه شما
      │
      │  یک رابط واحد
      ▼
┌────────────────────┐
│       میزبان       │
│ احراز هویت         │
│ محدودیت نرخ        │
│ صف درخواست‌ها      │
│ مسیریابی مدل       │
│ موازنه بار کلیدها  │
│ پایش سلامت         │
│ قطع‌کننده مدار     │
│ جابه‌جایی خودکار   │
└─────────┬──────────┘
          │
   ┌──────┼──────┬─────────┐
   ▼      ▼      ▼         ▼
 سرویس‌ها و مدل‌های خارجی
          │
          ▼
        پاسخ
```

نسخهٔ انگلیسی همین مستندات: [README.md](README.md)

## میزبان چیست؟

لایهٔ مرکزی بین برنامهٔ شما و سرویس‌های هوش مصنوعی؛ از جمله:

- دیپ‌سیک، جمینای، اوپن‌روتر، ان‌ویدیا
- زد‌ای‌آی، گپ‌جی‌پی‌تی، سرویس‌های مبتنی بر رپید
- سرویس‌های سازگار با قالب رایج گفتگو
- سرویس‌های سفارشی با درایور جدا

بدون چنین درگاهی، هر پروژه باید جداگانه آدرس سرویس، کلید، نام مدل، محدودیت، تلاش مجدد، صف و ثبت رویداد را پیاده کند. میزبان این کارها را متمرکز می‌کند؛ برنامهٔ شما لازم نیست بداند کدام سرویس پاسخ داده است.

---

## چرا میزبان؟

> برنامهٔ شما با یک رابط پایدار حرف بزند؛ پیچیدگی چند سرویس با میزبان باشد.

- یک اتصال به‌جای چند اتصال جدا
- مدیریت متمرکز از پنل مدیریت
- اگر یک مسیر قطع، کند یا تمام‌سهمیه شد، می‌توان مسیر جایگزین را امتحان کرد
- چند کلید برای یک سرویس و توزیع بار بین آن‌ها
- وابستگی کمتر به یک فروشنده
- اجرا روی هاست یا سرور خودتان
- قابل گسترش: بسیاری از سرویس‌های سازگار را فقط از پنل اضافه می‌کنید؛ فرمت خاص را با پوشهٔ درایورها پشتیبانی می‌کنید

## قابلیت‌های اصلی

### مدیریت سرویس‌ها و مدل‌ها

از پنل می‌توانید نام، شناسه، آدرس پایه، نوع، وضعیت، مدل‌ها و کلیدها را مدیریت کنید.  
مدل‌ها از سرویس‌ها جدا هستند و می‌توانند مدل جایگزین داشته باشند.

### مسیریابی درخواست

دو حالت اصلی:

- **مشخص:** کلاینت مدل را انتخاب می‌کند
- **عمومی:** میزبان خودش مسیر مناسب را برمی‌گزیند

انتخاب مسیر می‌تواند به سلامت سرویس، در دسترس بودن کلید، وزن، بار، تأخیر، وضعیت قطع‌کننده مدار، سیاست کلاینت و مدل جایگزین وابسته باشد.

### موازنه بار و جابه‌جایی خودکار

درخواست‌ها بین چند کلید یک سرویس پخش می‌شوند. در صورت خطا، طبق تنظیمات مسیر بعدی امتحان می‌شود.

### قطع‌کننده مدار و پایش سلامت

بعد از خطاهای پیاپی، مسیر موقتاً کنار گذاشته می‌شود تا به سرویس ناسالم فشار اضافه وارد نشود. امتیاز سلامت و تأخیر در مسیریابی نقش دارند.

### مدیریت کلیدها

کلیدهای سرویس در پنل مدیریت می‌شوند و در پایگاه‌داده به‌صورت رمزنگاری‌شده ذخیره می‌گردند. اگر کلید اصلی محیط تنظیم نشده باشد، سیستم عمداً از ذخیرهٔ ناامن کلید جلوگیری می‌کند.

> فایل محیط، کلید واقعی و نسخهٔ پشتیبان پایگاه‌داده را در مخزن عمومی قرار ندهید.

### مدیریت کلاینت‌ها

هر کلاینت می‌تواند داشته باشد:

- کد شناسایی
- رمز (به‌صورت هش)
- وضعیت فعال یا غیرفعال
- درجه از ۱ تا ۱۰ (اولویت و سطح دسترسی)
- محدودیت نرخ

سطح دسترسی بر اساس درجه:

- ۱ تا ۳: مدل‌های پایه
- ۴ تا ۷: مدل‌های گفتگو
- ۸ تا ۱۰: شامل بینایی، نویسه‌خوانی، عامل و ابزار

### محدودیت نرخ و صف

محدودیت در بازه‌های دقیقه، ساعت، روز و ماه پشتیبانی می‌شود.

وضعیت‌های صف:

```text
در صف → در حال اجرا → تکمیل‌شده
                      → ناموفق
                      → تلاش مجدد
                      → با تأخیر
                      → متوقف نهایی
```

### همزمان و ناهمزمان

- **همزمان:** کلاینت منتظر پاسخ سرویس می‌ماند
- **ناهمزمان:** درخواست پذیرفته می‌شود، در پس‌زمینه پردازش می‌گردد، سپس با پرس‌وجوی وضعیت و نتیجه، یا ارسال به آدرس بازگشت دریافت می‌شود

آدرس بازگشت فقط برای نشانی‌های عمومی مجاز است؛ آدرس‌های داخلی و محلی رد می‌شوند.

### ردیابی درخواست

برای هر درخواست وضعیت، سرویس، مدل، زمان‌ها، تعداد تلاش، نتیجه و خطا ذخیره می‌شود و در پنل و از طریق رابط وضعیت و نتیجه قابل مشاهده است.

### کلید تکرارنشدن و شناسهٔ رهگیری

می‌توانید برای جلوگیری از پردازش تکراری و اتصال رویدادها در سامانهٔ خودتان، شناسهٔ یکتا ارسال کنید:

```json
{
  "idempotency_key": "order-42",
  "correlation_id": "my-trace-1"
}
```

## چرخهٔ یک درخواست

```text
کلاینت
  → احراز هویت
  → محدودیت نرخ
  → اعتبارسنجی
  → صف
  → زمان‌بند
  → موازنه بار و استخر کلید و قطع‌کننده مدار
  → درایور سرویس
  → سرویس خارجی
  → نتیجه
```

### جدول مسیرها

| مسیر | روش | احراز هویت | کاربرد |
| --- | --- | --- | --- |
| `api.php?action=send` | POST | کلاینت | ارسال درخواست |
| `api.php?action=status&id=...` | GET | کلاینت یا مدیر | وضعیت درخواست |
| `api.php?action=result&id=...` | GET | کلاینت یا مدیر | دریافت نتیجه |
| `api.php?action=models` | GET | عمومی | فهرست مدل‌های فعال |
| `api.php?action=policy` | GET | کلاینت | سیاست کلاینت |
| `api.php?action=cost_models` | GET | عمومی | اطلاعات هزینه |
| `api.php?action=cost_estimate` | GET | عمومی | برآورد هزینه |
| `api.php?action=admin_*` | مختلف | نشست مدیر | مدیریت پنل |
| `cron.php?worker&token=...` | GET یا خط فرمان | توکن زمان‌بندی | پردازش پس‌زمینه |

### نمونهٔ درخواست همزمان

```bash
curl -X POST "https://YOUR_DOMAIN/api.php?action=send" \
  -H "Content-Type: application/json" \
  -H "X-Client-Code: miz_basic_001" \
  -H "X-Client-Secret: basic_secret_CHANGE_ME" \
  -d "{
        \"mode\": \"specific\",
        \"model\": \"gpt-4o-mini\",
        \"action\": \"chat\",
        \"payload\": {
          \"messages\": [{ \"role\": \"user\", \"content\": \"سلام!\" }]
        }
      }"
```

## نصب

### ۱) پایگاه‌داده

یک پایگاه‌داده و یک کاربر با دسترسی کامل روی همان پایگاه بسازید.

### ۲) آپلود

فایل‌های پروژه را در ریشهٔ وب یا زیرپوشه آپلود کنید.

### ۳) پیکربندی محیط

```bash
cp .env.example .env
```

نمونهٔ مقادیر:

```ini
MIZBAN_DB_NAME=your_db_name
MIZBAN_DB_USER=your_db_user
MIZBAN_DB_PASS=your_strong_password
MIZBAN_MASTER_SECRET=64_random_hex_chars
MIZBAN_CRON_TOKEN=random_secure_token
MIZBAN_ADMIN_USER=admin
MIZBAN_ADMIN_PASSWORD=admin123
```

ساخت مقدار تصادفی:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
php -r "echo bin2hex(random_bytes(16)), PHP_EOL;"
```

### ۴) اولین اجرا

آدرس زیر را یک‌بار باز کنید تا جدول‌ها ساخته شوند:

```text
https://YOUR_DOMAIN/index.php
```

اختیاری: وارد کردن پروندهٔ اسکیما یا اجرای مهاجرت.

```bash
php migrate.php
```

### ۵) عوض کردن گذرواژهٔ مدیر

بلافاصله بعد از ورود: پنل ← تغییر گذرواژه.

### ۶ تا ۸) پیکربندی از پنل

1. سرویس جدید (نام، شناسه، آدرس پایه، نوع)
2. افزودن کلیدها (رمزنگاری‌شده در پایگاه‌داده)
3. تعریف مدل‌ها (شناسه، نام نمایشی، سرویس، مدل جایگزین، وضعیت)

### حساب‌های آزمایشی

| نقش | مقدار |
| --- | --- |
| مدیر | `admin` / `admin123` |
| کلاینت پایه | `miz_basic_001` / `basic_secret_CHANGE_ME` |
| کلاینت ویژه | `miz_vip_001` / `vip_secret_CHANGE_ME` |

قبل از انتشار واقعی، این مقادیر را عوض یا حذف کنید.

### پردازش پس‌زمینه

```cron
* * * * * php /home/USER/public_html/cron.php worker
* * * * * php /home/USER/public_html/cron.php health
* * * * * php /home/USER/public_html/cron.php retry
* * * * * php /home/USER/public_html/cron.php lease_recovery
*/5 * * * * php /home/USER/public_html/cron.php stats
0 * * * * php /home/USER/public_html/cron.php cleanup
```

یا کارگر دائمی:

```bash
nohup php worker_runner.php --daemon &
```

فراخوانی از وب بدون توکن معتبر رد می‌شود.

## توسعه و آزمایش

```bash
php tests/smoke.php
for f in *.php; do php -l "$f"; done
php cron.php worker
```

- منطق اختصاصی هر سرویس را در پوشهٔ درایورها نگه دارید
- کلید و رمز را داخل کد ننویسید
- هر دو پروندهٔ ترجمه را هم‌کلید نگه دارید
- جریان اصلی درخواست را بدون دلیل تغییر ندهید

راهنمای مشارکت در پروندهٔ مربوط به مشارکت آمده است.

### افزودن سرویس جدید

- اگر قالب گفتگوی رایج را پشتیبانی می‌کند: معمولاً فقط از پنل
- اگر قالب خاص دارد: پوشهٔ درایور با پروندهٔ شناسه و در صورت نیاز درایور اختصاصی

## مناسب چه کسانی است؟

توسعه‌دهندگان، سامانه‌های نرم‌افزاری، وب‌سایت‌ها، ربات‌ها، افزونه‌ها و تیم‌هایی که می‌خواهند کلیدها و مسیریابی هوش مصنوعی را روی زیرساخت خود متمرکز کنند.

---

## اصول طراحی

1. پیچیدگی را از کلاینت دور کنید  
2. سرویس‌ها قابل جایگزینی بمانند  
3. در خطا تا حد ممکن نرم و با تلاش مجدد و مسیر جایگزین رفتار کنید  
4. اعتبارنامه‌ها خارج از برنامهٔ کلاینت و خارج از مخزن عمومی بمانند  
5. هسته سبک بماند  
6. افزودن سرویس جدید بدون بازنویسی کل سامانه ممکن باشد  
7. اولویت با اجرای خودمیزبان باشد
